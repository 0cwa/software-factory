# Plan-change factory runtime

The pinned SF-1 plan-change workflow is a fresh-execution-only runtime. A run is claimed by an exclusive private directory and held by a narrow private execution lock for the whole process. `resume` never dispatches or writes: terminal runs are read-only no-ops, while nonterminal runs (including unknown outcomes) are blockers for inspection or operator abandonment. Abandonment takes the same lock and preserves outcome uncertainty.

Runtime records are bounded v1 JSON and JSONL evidence. Intent is fsynced before a capability call; state, results, artifacts, and parent directories are made durable. Only digests, selected plan fields, bounded diagnostic codes, and canonical Protocol v4 receipt projections are persisted. The canonical capability port is `createPiProtocolCapabilityPort(fabric)`: it accepts only the public `mintPrincipal` and `invokeAs` methods, mints the fixed Factory principal, and attenuates each `pi_dev.scout` or `pi_dev.architect` call to its selected target, `fs.read`/`model.call`, depth zero, and one invocation.

The complete repository manifest includes tracked, ignored, generated, dependency, directory, regular-file, and symlink entries. It excludes only `.git` and the canonical runtime directory, never follows repository symlinks, and is compared before/after scout and at final acceptance. Any scout mutation prevents architect dispatch.

Dispatches have bounded absolute deadlines, cancellation, and a bounded grace period. A timeout or interrupted settlement becomes `outcome_unknown`; a canonical unknown receipt returned during grace may be retained, while a late terminal result never becomes success. There is no recovery engine, request persistence, SQLite store, lease renewal, CLI integration, discovery/preflight marketplace, or automatic retry.

The exact v4.0.0 release currently has an upstream packaging blocker: its `./core` export resolves to TypeScript and is not directly executable by plain Node. The focused upstream issue requesting a JavaScript runtime export and declarations is [Kybernetria/pi-protocol#5](https://github.com/Kybernetria/pi-protocol/issues/5). Production code therefore imports the public Protocol contract as types only and receives the runtime fabric explicitly.
